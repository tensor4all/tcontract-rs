# 2026-11-20 `t4a-desc`: the device-neutral grouped-GEMM job descriptor (#209)

The descriptor that cpueinsum's `GroupedPlan` (tensor4all/cpueinsum-rs#79), the
fused executor (#208), the strided-run route (tensor4all/cpueinsum-rs#78) and a
future GPU backend share. Design context: tensor4all-meta
`docs/design/symmetric-tensors-and-symtn.md` §3.1, "Job format". The public
surface was proposed on #209 first and implemented as approved; the
maintainer's decisions are in the [decision log](../decision-log.md#2026-11-20-the-device-neutral-job-descriptor-209).

## Shape of the crate

- A raw `GemmJob` is plain data with public fields and no invariant, like
  cuBLAS's argument arrays. All checking happens once, in `GemmBatch::new`,
  which owns the jobs and is immutable afterwards. Consumers hold the batch in
  their plan and lend buffers per execution, so the batch has no lifetime
  parameter and holds no buffer, pointer, executor or scalar value.
- Ops and `ScalarKind` are batch values because validation depends on them
  (ld minimum per op, byte spans per element size). `alpha`/`beta` are not:
  a dependency-free crate cannot do arithmetic on them, and today's
  `GroupedPlan` already takes them per execution.
- The partitions are stored, not recomputed: the groups (cuBLAS groups, #51
  children) as one flat id array plus ranges, the runs as one `GemmRun` per
  run, and `output_order`, the disjointness proof a consumer needs to split one
  mutable output.

## Choices that are not obvious from the code

- **Lowest-id errors without a second pass.** Per-job checks run in id order,
  so the first failure is the lowest id. For overlap, one sweep over the
  outputs sorted by `(start, id)` finds *every* overlapping job: a job
  overlaps an earlier one exactly when its start is below the running maximum
  end, and a later one exactly when the next start is below its end. The
  reported `job` is the minimum id over those, not the first pair in offset
  order (`reports_the_lowest_overlapping_id_not_the_first_in_offset_order`).
- **`check_lens` is O(1) on success** (compare against the stored maxima) and
  scans only on failure, to name the lowest id past the end rather than the
  job with the largest end.
- **No work-overflow error.** Once outputs are disjoint inside a buffer whose
  byte end fits `isize`, Σ m·n < 2^61, and k < 2^63, so Σ m·n·k < 2^124 fits
  `u128`. An error for it would be unreachable (REPOSITORY_RULES "Public
  Boundary Safety Audits"), so the sums saturate under an `INVARIANT`.
- **Empty operands still count their offset** towards `required_len`, as in
  cpueinsum's `prepare_jobs`, so a consumer can slice every operand without a
  special case. `check_fresh_cover` ignores empty jobs; its doc says the
  consumer also calls `check_lens`.
- **Runs need a positive C stride of at least the C footprint**
  `(n-1)·ldc + m` (#78's `rows·cols` generalised to `ldc > m`); A/B strides
  may be zero or negative. Runs are greedy from the left, as symtn's
  `strided_batch_runs`. With the interval overlap test, a positive C stride
  below the footprint cannot occur in a valid batch, so the test for that case
  checks that `new` rejects it.
- **`ScalarKind` and `Trans` are exhaustive** on purpose: a new kind or op
  must make every backend's `match` decide, and N/T/C is BLAS's closed set.
  `GemmError` is `#[non_exhaustive]`, because descriptor rules may grow.

## Verification

Unit tests in `crates/t4a-desc/src/gemm/tests/` cover the ld rules for every op
pair and operand, footprints under T/C and `ldc > m`, `k = 0`, zero-size jobs,
overflow and `isize` limits per scalar kind, lowest-id errors across error
kinds, the overlap sweep (adjacent, contained, interleaved `ldc > m`), the
fresh-output layout and coverage, groups, and every run case #78 lists. Every
public item has a running doctest.

## Not done here

- No consumer in this workspace yet. cpueinsum-rs#79 migrates `GroupedPlan`
  and deletes `GroupedGemmJob`, `GroupedOperand`, the job-validation variants
  of `GroupedError` and the hidden `PreparedGroupedJobs`, with no shim. Its
  call sites change from `(rows, contracted, cols)` to BLAS's `(m, n, k)`, so
  that PR rewrites every call site and checks them against the per-job oracle.
- The block-sparse descriptor (tensor4all/cpueinsum-rs#81).
- Unverified: whether `cublasGemmGroupedBatchedEx` accepts complex types; the
  13.1.1 header's typed forms are `S` and `D` only.
