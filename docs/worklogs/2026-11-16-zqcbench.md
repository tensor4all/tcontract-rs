# zqcbench: the complex-orbital benchmark member

> Third QC suite after `tcbench` and `qcbench`. The corpus, the extents and the
> selection are the benchmark job's
> `docs/tcontract-chem-complex-benchmark-plan.md` (Revision 3); this record
> covers the harness member itself and the decisions that shaped it.

## What landed

- `benchmarks/benchmarks/zqcbench/{main.rs, corpus.rs, corpus/tests.rs,
  README.md}`, the `[[bin]]` row in `benchmarks/Cargo.toml`, the
  `benchmarks/README.md` row and this log.
- **Ten corpora, 35 cases, 105 families, c64 only.** Three two-component spinor
  corpora (`cd-x2ccsd`, `cd-x2ceom`, `ri-ghf`), four periodic k-space corpora
  (`krccsd`, `ri-krbse`, `ri-krhf`, `ri-krgw`), the per-k-point AO→MO staging
  (`ri-kao2mo`) and two molecular spatial corpora (`somf`, `jk`). The driver
  accepts exactly `--dtype c64`; an `f64` request exits rather than measuring
  something else.
- **The shared modules are reused unedited** through `#[path]` (`engines/`,
  `knobs.rs`, `report.rs`, `blas.rs`, `ttgt.rs`, `tblis.rs`): the engines
  already drive c64 (tcbench publishes c64 rows), and everything
  complex-specific lives in this member's own `corpus.rs`. No shared-module PR.
- **Family-aware extents.** `Extents` carries the shared `(o, v)` pair and the
  rung-median `k = naux/nao`; `Family::{Spatial, Spinor}` resolves `ao` (`o+v`
  or `(o+v)/2`), `nso = 2*ao` and `naux = round(k*ao)`. The extents are the
  largest **even** `o` with `v = f*o` under a 12 GiB c64 A+B+C cell:
  `(o, v)` = (42, 126), (14, 140), (8, 160), giving 168/154/168 spatial AO,
  629/395/376 spatial aux, 84/77/84 spinor AO and 315/198/188 spinor aux.
- **The whole-binary budget is asserted.** The binding case is the `ao^4`
  exchange kernel `somf/cpscf.exchange_response` at 11.87 / 8.38 / 11.87 GiB of
  A+B+C. `corpus/tests.rs` pins the 12 GiB rule, the even-`o` rule and the
  binding case at every ratio; the README carries the process-peak model
  (A+B+2C ≈ 11.9 GiB without `blas`, 2A+2B+3C ≈ 23.7 GiB with it).
- **One case is batched.** `ri-krgw/sigma.contract` (`mnQ,nQl->mnl`) carries
  the batch index `n` in both operands and the output; the harness times the
  whole batched call, `mnk()` folds the batch extent into `m` (m = ao², n = ao,
  k = naux, `m·n·k` = the MAC count), and the corpus test's contraction
  invariant has the batch arm (qcbench's "exactly twice" form would fail here).
- **Selection and uniqueness are pinned.** The ten tags, the 35 literals, the
  per-case `macs` monomial, the three collision resolutions and the pairwise
  uniqueness key (operand-order invariant, `ao` and `nso` distinct domains) are
  tested, plus the degenerate-rung clause (both `jk` rows) and the id namespace
  (one tag per corpus, no double prefix: `ov_03/somf.coulomb`).
- **The memory budget moved from 8 GiB to 12 GiB** (Revision 3). The 8 GiB
  extents were 38/13/7, and 13 and 7 are odd: with `v = f*o` at f = 10/20 they
  make `o+v` odd, so `nso = o+v = 2*ao` cannot hold. The even-`o` extents are
  42/14/8; the 12 GiB cell keeps the verify peak A+B+2C ≈ 11.9 GiB below
  qcbench's 15 GiB, so the recording host class does not change.

## Why these choices

- **`ri-krbse` keeps both rung-1 rows.** The plan's earlier draft dropped
  `bse.screened` against `bse.coulomb` as "the same GEMM shape". They share the
  `o^2*v^2*naux` MAC count but not their operand domains (`Pia,Pjb->iajb` is
  `(ov)x(ov)` with `k = naux`; `Qij,Qab->ijab` is `o^2 x v^2` with `k = naux`),
  so the canonical keys differ and the strict rule keeps both. There is no
  backfill, and `bse.screened_left` (rung 3) is not selected.
- **`o` is even, checked against DIRAC 26.1.** An index count cannot be
  half-integral: `o+v = nso = 2*ao` must be even, and with `v = f*o` that means
  an even `o` at f = 10 and f = 20. DIRAC's 2c SCF references keep every
  occupied level a Kramers pair (H2O/X2C: nao 52, nso 104 = 2·52, o = 10;
  B with 5 electrons: o = 6; N with 7: o = 10), which is also what the corpora
  mean. The next even `o` values are 14.3 GiB (ov_10) and 14.3/29.0 GiB
  (ov_03/ov_20), so the budget, not a larger extent, is what stops there.
- **A 12 GiB cell, not 8.** The planar case for 8 GiB was the real bench's
  operand budget; the complex suite's binder is an `ao^4` input with a tiny
  `ao^2` output, so its process peak tracks A+B+C rather than 2C. At 12 GiB the
  peak is still below qcbench's 15 GiB and the recording host is unchanged; at
  8 GiB the even-`o` rule costs the spinor family and the budget is under-used.
- **No double prefix.** The plan's `<ratio>/<tag>.<case_id>` rule turns
  `somf.coulomb` + tag `somf` into `somf.somf.coulomb`; the member keeps the id
  when it already begins with its tag, so the family id is
  `ov_03/somf.coulomb`.
- **Docs.** The README states the transcription is not machine-checked here,
  the memory model with its `blas` condition, the one non-corpus `f64` row a
  verify log carries, and the batched case — the narrations the qcbench PR
  (#187) converged on.

## Verification

- `cargo test --release -p tcontract-bench --bin zqcbench` — 13 tests (11
  corpus + 2 shared `knobs`) pass.
- `cargo clippy -p tcontract-bench --all-targets -- -D warnings`,
  `cargo fmt --all -- --check`, `cargo deny check bans` and
  `scripts/check-no-public-rayon.sh` — clean.
- The `tblis` arm was smoke-built with `--features tblis13` against a local
  TBLIS 1.3.0 prefix (the campaign's v2.0-beta2 prefix is not on this
  development host) and a small `verify --engines plan,tblis` run agreed.
- `zqcbench info` reports the build; `--dtype f64` and `--size` exit 2 with the
  member's own messages.
