# 2026-11-19 `t4a-cost`: the cost-model types leave `tcontract-exec` (#205)

Follow-up to #194/#204: `tcontract-exec` had become the carrier of
`host::CpuClass`, `ItemTime` and (inside `tcontract`'s faer strategy) the
row-to-time rule of the generic fit, and tlinalg-rs#119 needs exactly those
three without depending on a contraction crate. Extracted into
`crates/t4a-cost`, a crate with no dependency at all.

## What moved, what stayed

- `CpuClass` (struct, `detect`, the `/proc/cpuinfo` parser and its tests)
  moved verbatim; `tcontract-exec`'s `host` re-exports it, so the 0.13 paths
  (`tcontract_exec::host::CpuClass`) keep resolving.
- `ItemTime` moved; `batch.rs` re-exports it, so `tcontract_exec::ItemTime`
  and `tcontract_exec::batch::ItemTime` keep resolving, and
  `BatchQuery::with_item_time` is untouched.
- The generic fit became `t4a_cost::ItemFit` (the `F, R, O, C, Q0, Q1` row of
  `experiments/faer-item-width/item_fit.py`) with one
  `ItemFit::item_time(muladds, split, slow_below)` rule; faer's `Row` is now
  that row plus its three features (`tile_m`, `tile_n`, `slow_cols`), and its
  fitted values are unchanged. The Python experiment stays where it is: the
  crate carries the contract, not the fit.
- The lane decision (`batch_decision*`, `BatchQuery`, `WorkModel`), the
  `HostClass`-keyed rate tables and the `HostClass` re-export stay in
  `tcontract-exec`: they are the token's and the decision's, and the
  neutrality constraint (no scheduler/pool/scratch, no `threadteam`
  dependency) would not survive them.

## Decisions

- **Re-export, not migrate, in `tcontract-exec`.** The issue allows either;
  the re-export keeps the 0.13 API and every doctest valid at zero cost, and
  `tcontract` reads the types from `t4a-cost` directly (the canonical home).
- **faer's `Row` nests `ItemFit` instead of keeping a flat local copy.** One
  row-to-`ItemTime` rule in the stack (the alternative — a private faer copy
  beside the generic one — is exactly the drift tlinalg#119's "same files,
  not a second implementation" agreement forbids). The old and new
  expressions are the same sequence — `work = muladds / R`, the two slow-share
  multiplications against that work, the tile-derived split and
  `n.div_ceil(slow_cols)` — so the produced `ItemTime` is bit-identical by
  construction; `strategy/faer_time/tests.rs` pins the behaviour it can reach
  (`the_fitted_class_ships_rows_for_all_but_f64` everywhere, and the
  argmin-of-the-host-row test on a fitted class — on this EPYC host its
  fitted branch is not exercised, because the class has no row).
- **`t4a-cost` 0.1.0, `publish = true`** with description/readme/license, but
  no publish from this PR: REPOSITORY_RULES.md requires the maintainer's
  approval per package. `tcontract-exec` keeps 0.13.0; its release train owns
  the bump.
- Version note for consumers: `tcontract-exec` now depends on `t4a-cost`
  `^0.1.0`, so the two release together from here.

## Remaining constraints

- tlinalg-rs#119 can consume `t4a_cost::{CpuClass, ItemFit, ItemTime}`
  (tlinalg fits its own rows and supplies its features per item);
  `batch_decision_within` still lives in `tcontract-exec`, so its port needs
  the dependency step it already planned.
- `ItemFit` is the contract of `item_fit.py` as it stands; a fit-script change
  that adds or renames a parameter is a crate-breaking change and should go
  through both crates.
