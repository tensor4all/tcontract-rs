# faer 0.24 vs tensorcontract: GEMM strategy on AMD EPYC 7713P (Zen 3)

Read-only source study, 2026-09-30. Nothing was run except `rustc --print cfg` and reads of sysfs and /proc.
Items marked **[inf]** are my own inferences or arithmetic from the source. They were not measured.

Abbreviations:
- `PG` = private-gemm-x86 0.1.20, `~/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/private-gemm-x86-0.1.20/`
- `FA` = faer 0.24.4, same registry directory
- `TC` = `~/tensor4all/tcontract-rs/tensorprimitives/crates/tensorcontract/src/`

## 0. Machine and build facts (verified)

- `/proc/cpuinfo`: AMD EPYC 7713P. Flags include avx, avx2 and fma. There is no avx512.
- SMT is off (`/sys/devices/system/cpu/smt/active` = 0).
- Caches reported by sysfs for cpu0:
  - L1d: 32K, 8-way, 64 B lines, private.
  - L2: 512K, 8-way, private.
  - L3: 32768K, 16-way, shared by CPUs 0-7 (one CCD).
- `rustc --print cfg` with no flags enables only fxsr, sse and sse2. With `-C target-cpu=native` it adds avx, avx2, fma and bmi2.
- tcontract-rs has no `.cargo/config*`. `~/.cargo/config.toml` sets only kache and incremental. `$RUSTFLAGS` is empty. CI sets only `RUSTFLAGS=-D warnings` (.github/workflows/ci.yml:10).
  - So **no target-cpu is used**. Everything outside explicit `#[target_feature]` code and inline asm is compiled for baseline SSE2.
- Release profile: `opt-level=3`, `lto="thin"`, `codegen-units=1` (Cargo.toml:69-73).
- Cargo.lock versions: faer 0.24.4, faer-traits 0.24.0, gemm/gemm-common/gemm-f64/gemm-c64 0.19.0, nano-gemm 0.2.2 (f64 and c64 0.2.1), **private-gemm-x86 0.1.20**, spindle 0.2.6, pulp 0.22.3, rayon 1.12.0, num_cpus 1.17.0.
- Benchmark path (benchmarks/benchmarks/tcontract/contract/contract.rs:204): `Strategy::PermuteGemm` (faer) is compared with `Strategy::Tblis` (tensorcontract). Both run on the same dedicated rayon pool (`benchmarks/src/threads.rs:80-96`), pinned with taskset inside one CCD.
  - faer is entered with `exec.install` and then `faer::Par::rayon(n)` (tprims-blas/src/gemm.rs:34-37, 142-146).
  - tensorcontract is entered with `Plan::run_raw_with(&ExecSpmd)`, which calls rayon `ThreadPool::broadcast` (tcontract/src/tblis.rs:15-27, 113-126; tcontract-exec/src/exec.rs:200-245).
  - Both backends get the same width model (`width_for`: serial below 50 µs, otherwise cost = 5 µs + 5 µs·k + S/k, at 0.05 ns/flop).
  - **So thread count and pool are the same for both. The gap is inside the libraries.**

### Important correction to the premise

On this CPU, faer does **not** run Sarah Quiñones's `gemm` / `gemm-common` / `gemm-f64` / `gemm-c64`. `matmul_imp` works like this:

1. It first peels off special cases: matvec when n==1 or m==1 (FA src/linalg/matmul/mod.rs:1214-1281), and rank-1 update when k==1 (1283-1310).
2. If M·N·K ≤ 16³ = 4096, it calls `nano_gemm` (mod.rs:16, 1329).
3. Otherwise it calls **`private_gemm_x86::gemm`** whenever `is_x86_feature_detected!("avx512f")`, or `("avx2") && ("fma")` (mod.rs:1357-1406).
4. `gemm::gemm` (mod.rs:1416) is reached only on x86 CPUs without AVX2+FMA, or builds without `std`.

private-gemm-x86 is a separate crate (repository `sarah-quinones/gemm-x64-v2`). Its build.rs (81 KB) generates **hand-scheduled x86 assembly**, included with `include!(…asm.rs)` (PG src/lib.rs:13). The gemm-* crates are compiled but not reached here.

## 1. ISA dispatch

**faer / PG**
- Runtime detection: `is_x86_feature_detected!` on every call (FA mod.rs:1359-1367). This passes `InstrSet::Avx256` on this machine.
- `PG::gemm` then chooses the kernel table by (instruction set, dtype) (PG lib.rs:1252-1269):
  - f64: `F64_SIMD256`, mr=12, nr=4 (lib.rs:1254).
  - c64: `C64_SIMD256`, mr=6, nr=4 (lib.rs:1256).
- The kernels are assembly, so RUSTFLAGS and target-cpu have no effect on them.
- faer's own `nightly` feature is what switches pulp/gemm/nano-gemm to x86-v4. It is not enabled here.

**tensorcontract**
- Runtime detection is cached in a `OnceLock`: `have_avx512()` and `have_avx2()` (`is_x86_feature_detected!("avx2") && ("fma")`) (TC kernel/x86.rs:425-456).
- `pick_isa` takes the first available ISA, and can be overridden with `TENSORCONTRACT_KERNEL` (x86.rs:494-509). On this machine it picks **Avx2**.
- The kernels are Rust intrinsics generated by `simd_kernels!` under `#[target_feature(enable="avx2","fma")]` (x86.rs:118-130, kernel/simd.rs:54-120).
- They are called through plain-fn trampolines, which means one indirect call per micro-tile (simd.rs:243-300).
- Packing, write-back and the driver have no `#[target_feature]`. With no target-cpu they are compiled for **SSE2 baseline** **[inf, from the build flags above]**.

## 2. Micro-kernel register tiles

| | faer / PG (AVX2) | tensorcontract (AVX2) |
|---|---|---|
| f64 MR×NR | **12×4** (3 ymm A × 4 bcast; 12 acc) (PG lib.rs:1254; build.rs:3257-3262 instantiates m=1..3 vectors × n=1..4, plus n up to 8 for m=1) | **8×6** (MV=2 × NR=6; 12 acc, 15 live) (TC x86.rs:356) |
| c64 MR×NR | **6×4** complex (3 ymm × 4; 12 acc) (lib.rs:1256) | **planar 4×5** (MV=1 × NR=5; 10 acc, 14 live) (x86.rs:357). 1m/3m can be chosen with `TENSORCONTRACT_COMPLEX`, but planar is the default (kernel/mod.rs:211-217) |
| loads per k-step, f64 | 3 A + 4 bcast = 7, for 12 FMA | 2 A + 6 bcast = 8, for 12 FMA |
| loads per k-step, c64 | 3 A + 8 bcast (re, im) = 11, for 24 FMA-addsub, plus 3 `vpermilpd` | 2 A + 10 bcast = 12, for 20 FMA |
| complex scheme | Native interleaved complex. A real-part broadcast goes into `vfmaddsub231pd`. Then A is swapped with `vpermilpd` (vswap) and an imag-part broadcast goes into `vfmaddsub231pd` again (build.rs:1186-1193, 1291-1299, 2518-2580). The sign pattern is fixed afterwards by an XOR with the flip.re/flip.im constants, which also encodes conj (build.rs:2194-2247, 3307-3314) | Split (planar) re/im panels made by packing. 4 FMAs per (A-vector, B-scalar) pair: cr+=ar·br, cr-=ai·bi, ci+=ar·bi, ci+=ai·br (simd.rs:118-160). Conj is folded into packing (pack.rs:137) |
| k-unroll | `unroll = 2` only when `m·n ≤ 6 && !need_mask`, and `need_mask = simd.sizeof() >= 16` is true for every 128/256/512-bit kernel. So **every AVX2 tile, 12×4 and 6×4 included, has no k-unroll** (build.rs:1952-1954) | None explicit. A plain `for p in 0..kc` loop, left to LLVM (simd.rs:83-98) |
| software prefetch | None (no `prefetch` anywhere in PG build.rs or lib.rs) | None |
| where results go | Directly into dst in the asm epilogue: alpha multiply, then store or add, with masked edge variants (build.rs:2188-2300) | Into a scratch **tile buffer** `ab`. Scalar `writeback` then adds it into D (driver.rs:769-815) |

Dependency-chain slack **[inf]**. Zen 3 FMA latency is 4 cycles and there are 2 FMA pipes.
- tensorcontract planar 4×5: each accumulator takes 2 dependent FMAs per k-step, an 8-cycle chain, against 10 cycles of FMA throughput. That is close to latency-bound.
- faer c64: 8-cycle chain against 12 cycles.
- f64 is comfortable in both: 4 vs 6 cycles.
- The tensorcontract source itself says its AVX2 shapes are **"provisional and unmeasured"** (x86.rs:71, 255, 363). Its measurement record is for AVX-512 Xeons.

## 3. Cache blocking (KC / MC / NC)

### faer / PG

**KC.** `kc = min(k, 512)`, fixed (PG lib.rs:1272).

**Cache sizes.** Probed once into a `OnceLock` (PG cache.rs:348-378). On Linux it walks `/sys/devices/system/cpu/cpu*/cache/index*` (cache.rs:14-148). It falls back to `lscpu`, then CPUID leaf 0x8000_0006 on AMD (250-284).
- Each level is stored as `size / shared_cpu_count`.
- L3 is then **multiplied by `num_cpus::get_physical()`** (cache.rs:146). On Linux that counts cores from /proc/cpuinfo, **ignoring affinity**: 64 here (num_cpus-1.17.0/src/linux.rs:59-101).
- Resulting values on this machine **[inf]**: L1 = 32 KiB, L2 = 512 KiB, **L3 = 32 MiB / 8 × 64 = 256 MiB** (effectively the whole socket, not the CCD).

**Per-kc normalisation.** Cache sizes are converted to "rows of kc" as `lX = bytes/sizeof/64/f`, with f = ceil(kc/64) (lib.rs:1338-1344). For f64 at kc = 512: l1 = 8, **l2 = 128**, l3 = 65536. For c64: l2 = 64, l3 = 32768 **[inf]**.

**Direct serial path.** At 1T with `!tall && m < l2 && n < l2`, PG calls one `millikernel_colmajor` over the whole matrix (lib.rs:1387-1410). For f64 at k ≥ 512 this means m, n < 128. The bound grows as k shrinks, e.g. 256 at k = 256.

**Otherwise, 1T.** A nested blocking with `row_chunk = [m, l3, l2, l2/2, mr]` and `col_chunk = [n, 2·l3, l3/2, l2, nr]` (lib.rs:1419-1424), rounded and normalised (1428-1454), and traversed by `kernel_imp` (lib.rs:910-1117).

Worked example for f64, m = n = 2048, kc = 512 **[inf]**:
- rows: [2048, 256, 128, 64, 12]
- cols: [65536, 65536, 32768, 128, 4]
- **The innermost block is 64 rows × 128 cols** (the A block is 64·512·8 B = 256 KiB, half of L2). The B micro-panel is 4 × 512 × 8 B = 16 KiB, which fits in L1.
- Levels whose chunk exceeds l3/2 get `packed_*_rs = 0` (lib.rs:1463-1466). So **NC is effectively infinite** on this box, because L3 was inflated to 256 MiB.
- For c64 the innermost block is 32 rows × 64 cols **[inf]**.

**Multithreaded.** `row_chunk = [m, m, m, l3/16·16, mr]`, `col_chunk = [n, n, n, l3/16·16, nr]` (lib.rs:1412-1418). One `millikernel_par` covers the whole m×n for each kc slab (up to 65536 rows).

**Pack buffer.** A thread-local `Vec<Page>`, with 4096-B aligned pages sized from the (inflated) L3: about 256 MiB each for A and B. It is reserved but uninitialised, so only touched pages are backed. It is **reused across calls**, and falls back to a fresh Vec if re-entered (lib.rs:1280-1318).

### tensorcontract

Default `BlockModel::Legacy` (kernel/cache.rs:786-793, 852-858). `Blocking::derive` (kernel/mod.rs:386-424) gives:
- `kc = 256` for 8-byte reals (384 for 4-byte). Can be overridden with `TENSORCONTRACT_KC_COUPLE`.
- `mc = 512 KiB / (kc · a_reals · 8)`
- `nc = 3 MiB / (kc · b_reals · 8)`
- Then rounded up to multiples of MR and NR (`with_blocking`, kernel/mod.rs:544-549).

Values on this machine:
- **f64 real: kc = 256, mc = 256, nc = 1536**
- **c64 planar: kc = 256, mc = 128, nc = 770** (768 rounded to NR = 5)

In both, the packed A block is exactly **512 KiB, i.e. 100 % of Zen 3's L2**. The constants were chosen as "half of a 1 MiB L2" for the Xeon Gold 6244 reference machine (mod.rs:417-419). The driver clamps mc to `m.next_multiple_of(mr)` and nc to n (driver.rs:448-450), but not to the thread's M strip.
- **[inf]** At 1T with m ≥ 256 (f64) or m ≥ 128 (c64), A_c cannot stay L2-resident alongside the B sliver and C lines, so it streams from L3.

**Analytical model (off by default, `TENSORCONTRACT_BLOCKMODEL=model`).** It uses BLIS-paper formulas on probed sysfs (cache.rs:916-1010), reading only cpu0's sysfs (cache.rs:458-). On this box it would give **[inf]**:
- kc = 256
- mc = 192 (6 of 8 L2 ways)
- nc ≈ 14336 at 1T, ≈ 13312 at 8T

Each `execute` allocates fresh `Panel`s (64-B aligned, `std::alloc`) (buffer.rs:1-48):
- the shared B panel (`pn · b_group`, about 3 MiB for f64 at full nc)
- a per-thread A block (512 KiB)
- a per-thread tile

These are at driver.rs:500-503, 543-544 and 575-576, and they are freed on return. Scatter vectors (`build_block_scatter`) are also allocated per call (driver.rs:427-434).

## 4. Packing

### faer / PG

**RHS (B) is never packed for non-tall problems.** `pack_rhs = tall`, where `tall = m ≥ 1.5·n && m ≥ l3` (lib.rs:1345-1347), and l3 is 65536 rows here, so tall never holds in practice. The kernel broadcasts B elements straight from the source with `rhs_rs`/`rhs_cs` strides: 4 column streams, each sequential in k (build.rs:2455-2470).

**LHS (A)** gets `pack_lhs = n > 3·nr·n_threads || lhs_rs != sizeof || (n > 6·nr && tall)` (lib.rs:1346).
- If A is not unit-row-stride, a separate asm pack routine plus a scalar fallback runs (lib.rs:338-341, 568-690).
- If A is column-major with unit row stride, **no separate pack pass exists**. The micro-kernel's "packA" variant loads A from source and stores each loaded vector to the packed buffer while computing the first column panel (build.rs:2437-2451, 2511-2513; dispatch at 2140-2175). Later column panels see `lhs = null` and read the packed copy (lib.rs:404-408).
- So packing is **fused with compute and with strided reads**.
- Skipped entirely when n ≤ 3·nr·t (n ≤ 12 at 1T; ≤ 96 at 8T): A is then read in place.

**Tiny and special cases.** nano-gemm for MNK ≤ 4096. Matvec and rank-1 paths as in §0.

### tensorcontract

**Always packs both A and B**, following TBLIS (pack.rs:54-107).
- Both are scalar element-by-element copies driven by `kscat` offset vectors (one i64 lookup per k), with a per-element `emit` that matches on `PackFormat` (pack.rs:125-155).
- There is a fast path for regular blocks (`bs == 1`, or a constant stride `bs`) and a gather path for irregular ones. There is no SIMD and no `#[target_feature]` (SSE2 baseline **[inf]**).
- Complex operands are de-interleaved into planar form while packing, and conj negates imag there.
- Edge slivers are zero-padded, so the kernel always runs full MR×NR.
- **B** is packed once per (jc, pc) into the shared panel, cooperatively by the pm threads of a column group (driver.rs:708-729).
- **A** is packed per (ic, pc) into each thread's private block (driver.rs:743-752).
- Pack buffers are 64-B aligned and allocated per call (see §3).

## 5. Threading

### faer / PG (with `Par::rayon(n)`, n from tcontract `width_for`)

**Serial threshold.** `n_threads = par.degree()` only if M·N·K ≥ 4096·sizeof(T), i.e. ≥ 32768 for f64 and ≥ 65536 for c64. Otherwise 1 (FA mod.rs:1403-1411).

**Worker pool.** `spindle::with_lock(n, f)` (PG lib.rs:1507-1515) takes `min(n, rayon::current_num_threads())`. It opens a `rayon::scope` and spawns n-1 workers that **spin-wait** between tasks (up to `SPIN_LIMIT` = 65536 pause iterations, then a futex) for the **whole GEMM call** (spindle-0.2.6/src/lib.rs:205-300, 410-470, 93).

**Per kc slab.** `MilliPar::call` (lib.rs:777-907) works as follows:
- The optional B pack (only when packing B) is split over **k** across threads (lib.rs:830-866).
- The m×n output is cut into **2-D jobs of (mf·mr) × (nf·nr)**:
  - `mf = clamp(ceil(ceil(m/mr) / (2t)), 2, 4)`, so 24-48 rows for f64 and 12-24 for c64.
  - `nf = 32/nr = 8`, so **32 columns** (lib.rs:813-822). The earlier `nf` is overwritten.
- Jobs are pulled dynamically with `gtid.fetch_add` (lib.rs:871-906).
- Job ids are ordered row-block-fastest (`thd_id0 = tid % n_threads0`, lib.rs:451-455). So at any moment all threads work on the **same 32-column strip of unpacked B**, which is shared through L2/L3 **[inf]**, while each packs or reads a different A row panel.

**Sharing packed A.**
- Whichever thread first reaches row panel i packs it (fused), then publishes `pack_lhs_job[i] = 2` with Release (lib.rs:490-555).
- Others check it with Acquire and use the packed copy.
- The check-then-store is racy, so two threads can pack the same panel at once. They write identical data, so the only cost is duplicated work.
- **No barrier inside a slab**, only spindle's fork/join per `for_each_raw`: one or two per kc slab, spin-based.

**NUMA and placement.** Buffers are the caller thread's TLS. The workers are pool threads, pinned to one CCD by taskset.

### tensorcontract (with `ExecSpmd`, rayon `broadcast` of width p)

**Partition.** `Plan::partition_with` (plan.rs:669-720).
- If `panels = ceil(m/mr) ≥ p`, it returns **(pm = p, pn = 1)**: a pure **1-D M split**.
- The column swap (`columns_beat_rows`) only fires when the threads span more than one L3 domain (plan.rs:1095-1097), so not on one CCD.
- Otherwise it minimises a small cost model over 2-D (pm, pn) (plan.rs:708-720).

**Loop nest per thread** (driver.rs:673-829): for each jc (nc):
1. for each pc (kc):
2. `Barrier::wait`
3. cooperative pack of this group's B slivers
4. `Barrier::wait`
5. for each ic (mc, within the thread's M strip): pack private A
6. for each jr (nr), for each ir (mr): kernel into tile, then scalar writeback to D.

Details:
- `std::sync::Barrier` is Mutex+Condvar, so futex sleep and wake. **Two barriers per (jc, pc) iteration** (driver.rs:554-571, 708-729).
- Packing and compute do not overlap across the barrier.
- Static partition, no work stealing. Each thread owns disjoint output rows, so results are bitwise identical for any thread count (plan.rs:570-584).

**Entry and thresholds.**
- Default thread count comes from `TENSORCONTRACT_THREADS` or 1 (plan.rs:1173-1179). tcontract overrides it with the spmd width.
- If spmd `broadcast` fails, it runs single-threaded; with no spmd, it spawns scoped threads per call (driver.rs:586-608).
- There is no small-problem serial threshold inside tensorcontract. tcontract's `width_for` is the only guard.

## 6. Other notable differences

- **alpha/beta.**
  - PG: beta is either Replace (overwrite, C not read, so NaN in C is not propagated) or Add. It becomes Add after the first kc slab (lib.rs:1356-1360, 1503). Alpha is applied in registers in every epilogue, including when alpha == 1 (build.rs:2248-2265). tcontract pre-scales C when beta ∉ {0, 1} (tprims-blas gemm.rs:84-94).
  - tensorcontract: `writeback` has a "plain" fast path (beta == 0, alpha == 1, no conj). Every later kc block runs the general path: `from_parts(...).mul(alpha)` (a complex multiply for c64 even when alpha == 1), then a load of D, an add and a store of D, all scalar (writeback.rs:112-184, 234-260).
  - Consequence: tensorcontract makes **ceil(k/kc) scalar read-modify-write passes over D, with kc = 256**. PG makes ceil(k/512) register-epilogue passes.
- **Edges.**
  - PG: kernel variants for every (m-vectors ≤ 3, n ≤ 4), chosen by jumps at kernel entry (build.rs:2004-2015), plus masked loads and stores for partial vectors. dst must have unit row stride for the vector epilogue; otherwise `epilogue_any` (build.rs:2267-2272).
  - tensorcontract: zero-padded packs, full kernel always, writeback of only mrem×nrem.
- **Conj.**
  - PG: `FLAGS_CONJ_LHS` and `FLAGS_CONJ_NEQ` select a conj kernel body (`vfma231_conj`) and adjust the epilogue XOR masks (lib.rs:1361-1362; build.rs:2398-2410, 2211-2247).
  - tensorcontract: conj is free, applied in the pack.
- **Output layout.** PG swaps to make dst column-major (`|dst_rs| ≤ |dst_cs|`), transposing the problem if needed (lib.rs:1221-1236). tensorcontract does the same through `plan.transposes_gemm(mr)` (driver.rs:375-400).

## 7. Ranked likely causes of the gap, with tests

How the items map onto the two measured numbers **[inf]**:
- #1 and #5 are the **base gap** that already shows at 1T (1.1-1.2×).
- #2 and #3 (and #4, but only when m/8 ≥ mc) are what makes the gap **widen from 1T to 8T** (up to 2.5×). These are sync, allocation and phase-structure costs that grow with thread count and shrink per-thread work. The kernel itself is the same code at every thread count.

Each item gives what it predicts and how to confirm it. None of this has been measured.

1. **Extra memory passes and scalar non-kernel code in tensorcontract. Main suspect for the 1.1-1.2× at 1T.**
   - faer: B is never packed, A is packed fused inside the kernel, and C is updated from registers once per 512-deep slab.
   - tensorcontract: separate scalar A and B packs, a scratch tile, and a scalar SSE2 writeback with a complex alpha multiply, repeated every 256 of k.
   - Rough size of the writeback **[inf]**: per f64 micro-tile per kc there are ~1536 FMA-cycles against 48 scalar RMW elements. That is likely a mid-single-digit % overhead.
   - Rough size of the packing **[inf]**: two separate scalar passes read and write about (m·ceil(n/nc) + n)·k elements; A is re-packed once per jc block. faer has no separate pass (B unpacked, A packed inside the kernel). For 1024³ this is plausibly as large as the writeback term or larger.
   - Tests:
     - `perf record` the 1T run and read the split between `writeback`/`pack_panel` and the kernel.
     - `TENSORCONTRACT_KC=512` (halves writeback passes; check mc and nc too).
     - Rebuild tensorcontract with `RUSTFLAGS=-C target-cpu=native` (or add `#[target_feature]` to pack and writeback) and check whether 1T closes.
2. **Synchronisation and phase structure at 8T.**
   - tensorcontract does 2 futex `std::sync::Barrier` waits per (jc, pc), with a non-overlapped cooperative B pack between them, and a static 1-D split.
   - faer uses spin-waiting spindle workers, dynamic 2-D stealing of 48×32 tiles, no intra-slab barrier and no B pack.
   - Tests:
     - `perf stat -e context-switches,cpu-migrations` and `perf sched latency` on the 8T run.
     - Instrument `bar.wait()` time (rdtsc around driver.rs:710 and 727).
     - Pin `TENSORCONTRACT_PARTITION` to a few (pm, pn) values. The benchmark harness forbids this variable (benchmarks/src/threads.rs:27), so use a standalone example.
     - Swap `std::sync::Barrier` for a spin barrier in a throwaway worktree and remeasure.
3. **Per-call allocation and first-touch in tensorcontract, versus persistent TLS pages in faer.**
   - tensorcontract allocates the B panel (~3 MiB) plus 512 KiB A per thread on every call, and frees them after. glibc may mmap and munmap or trim them, which gives page faults on every call.
   - Tests:
     - `perf stat -e page-faults,minor-faults` per iteration.
     - `strace -f -c -e mmap,munmap,brk,madvise`.
     - `MALLOC_MMAP_THRESHOLD_=67108864 MALLOC_TRIM_THRESHOLD_=…` as an A/B.
   - This matters most at small and mid sizes and at 8T, where 8 A blocks and the B panel are allocated at once.
4. **L2 blocking tuned for a 1 MiB L2.**
   - tensorcontract's legacy mc makes A_c = 512 KiB, all of Zen 3's L2 (f64 mc = 256, c64 mc = 128). faer's inner block is 256 KiB (64 rows f64, 32 rows c64 at kc = 512).
   - Tests:
     - `TENSORCONTRACT_MC_PCT=50` (and 37).
     - `TENSORCONTRACT_BLOCKMODEL=model` (mc = 192).
     - `perf stat -e l2_cache_req_stat.ls_rd_blk_c,ls_refills_from_sys.*` (Zen 3 L2-miss events).
   - Should matter at 1T for m ≥ 256, and at 8T only when m/8 ≥ mc.
5. **Micro-kernel quality.**
   - Hand-scheduled asm with 12 accumulators (both dtypes), versus unmeasured intrinsics shapes. Planar 4×5 has 10 accumulators with 2-deep chains (8 of 10 cycles), and there is an indirect call per micro-tile and half the depth per call.
   - Tests:
     - `cargo run --release -p tensorcontract --example kernel_shapes` under `TENSORCONTRACT_KERNEL=avx2` when the host is free (GF/s per shape against the ~2×4×… Zen 3 peak).
     - Compare with a PG micro-benchmark: call `private_gemm_x86::gemm` on m=12, n=4, k=512 in a loop.
     - Try `TENSORCONTRACT_COMPLEX=1m` (real 8×6 kernel on the 1e format) for c64.
6. **Shared B traffic at 8T (minor or unclear).**
   - faer's threads all stream the same unpacked 32-column B strip, so it is L3/L2-shared, with no pack write.
   - tensorcontract writes a packed B once and then all threads read it from L3.
   - Probably second-order. Could be probed with `perf stat -e l3_…` per thread count.

Suggested first measurement: `perf record -g` on one 1T and one 8T tblis case (f64 and c64, e.g. 1024³), then attribute cycles to kernel / pack / writeback / barrier / page-fault. That separates hypotheses 1-3 in one run.
